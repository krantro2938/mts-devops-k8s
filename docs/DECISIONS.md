# Технические решения и их обоснование

| Вопрос | Выбор | Альтернативы | Почему |
|---|---|---|---|
| Кластер | **kubeadm** v1.36, 1 узел (+ опциональные worker'ы) | kind, minikube, k3d, k3s | Приоритет по условию; «ванильный» Kubernetes без вендорских надстроек, тот же путь, что и в production. Скрипт поддерживает добавление worker-узлов. |
| Runtime | **containerd 2.2** + runc из upstream-релизов (sha256) | containerd из apt Ubuntu / Docker | Предсказуемая версия, совместимая с Kubernetes 1.36 (линейка 2.x), независимость от пакетов Docker; systemd cgroup driver. |
| CNI | **Calico** (VXLAN, BGP выкл.) | Flannel, Cilium | Flannel не реализует NetworkPolicy; Cilium тяжелее и сложнее в эксплуатации на 1 узле. Calico — стандарт де-факто, поддерживает NetworkPolicy, ставится оператором. |
| Реализация Gateway API | **Envoy Gateway** | Cilium Gateway, Istio, NGINX Gateway Fabric, Traefik, Kong | Проект CNCF «Gateway API first» (без Ingress-наследия), полная поддержка standard channel v1.6, богатые политики (rate limit, retry, auth, client/backend traffic) через Policy Attachment, качественные Prometheus-метрики Envoy из коробки, не требует замены CNI (в отличие от Cilium) и service mesh (в отличие от Istio). |
| Публикация Gateway | Service **NodePort** с фиксированными портами 30080/30443 (через `EnvoyProxy`) | MetalLB, hostNetwork | Нет облачного LB; NodePort не требует пула IP и прав на сеть стенда эксперта, адрес предсказуем для проверочных curl. MetalLB — в списке развития. |
| Приложение | **nginx** (`nginx-unprivileged`) + конфиг из ConfigMap, sidecar nginx-prometheus-exporter | своё приложение, httpbin | Условие: свой код не нужен. Образ публичный, non-root; JSON access-лог; отдельные v1/v2 для демонстрации маршрутизации. Упаковано своим Helm-чартом. |
| Мониторинг | **kube-prometheus-stack** (Prometheus Operator) | «голый» Prometheus | Декларативные PodMonitor/ServiceMonitor/PrometheusRule рядом с каждым компонентом, Grafana и Alertmanager, готовые правила/дашборды для Kubernetes. |
| Сборщик логов | **Fluentd** (DaemonSet, официальный Helm-chart и образ `fluentd-kubernetes-daemonset`) | Filebeat | Fluentd — проект CNCF, образ уже содержит нужные плагины (CRI-парсер, kubernetes_metadata, concat, prometheus); гибкий пайплайн (разбор JSON, классификация access/error), вывод по HTTP без сторонних плагинов. Filebeat тянет за собой стек Elastic. |
| Хранилище логов | **VictoriaLogs** | Elasticsearch/OpenSearch + Kibana, Loki | ES/OpenSearch требуют ≥1–2 GB RAM только под JVM — непозволительно на одном узле; у Loki нет готового Fluentd-плагина в официальном образе Fluentd (нужен свой образ). VictoriaLogs — один бинарник ~50–100 MB RAM, полнотекстовый поиск по всем полям (LogsQL), встроенный UI, плагин Grafana, приём JSON lines по HTTP. |
| TLS | **cert-manager** + собственный CA | openssl в скрипте, Let's Encrypt | Декларативный выпуск и авто-обновление сертификата; ACME невозможен для `demo.local` без публичного DNS. Замена на ACME — одна смена `issuerRef`. |
| Доступ к UI | HTTPRoute по hostname + Basic Auth (`SecurityPolicy`) на Gateway | port-forward | Демонстрирует ещё один сценарий Gateway API; пароль случайный, генерируется при деплое, в git не попадает. |
| Автоматизация | bash + Helm + Kustomize, `Makefile` | Ansible, Terraform | Минимум зависимостей на машине эксперта (только bash/curl/git на Ubuntu), прозрачные шаги, идемпотентность через проверку состояния и декларативные `helm upgrade --install` / `kubectl apply --server-side`. |
| Проверка | `smoke-test.sh` + CI (GitHub Actions на Ubuntu 24.04 с настоящим kubeadm) | ручная проверка | Каждое изменение доказуемо воспроизводится на чистой Ubuntu 24.04 двумя прогонами подряд (идемпотентность). |
