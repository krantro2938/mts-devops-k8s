Ревью работы и потенциальное масштабирование

Главная особенность

Решение доказуемо воспроизводимо: одна команда доводит чистую Ubuntu 24.04 до работающего кластера с Gateway API, метриками и логами, а CI на каждом коммите проходит этот путь дважды с 42 проверками. Наблюдаемость сквозная: один запрос с X-Request-ID находится в логах Envoy и nginx, а его код ответа и задержка видны в Prometheus.

Самое сложное решение

Выбор хранилища логов для Fluentd: Elasticsearch требует 1–2 GB памяти только под JVM, а для Loki нет плагина в официальном образе Fluentd — пришлось бы собирать свой образ. Выбран VictoriaLogs: около 100 MB памяти, приём JSON встроенным HTTP-выводом Fluentd, полнотекстовый поиск, свой интерфейс и плагин для Grafana.
